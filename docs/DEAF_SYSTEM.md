# THE DEAF SYSTEM — the caves are the story, and the growth doctrine

Owner's ruling (2026-08-15): the caves inside the map ARE the story, and the
world grows through caves from now on.

## The lore

When the corrupted song first played, the broken were the lucky ones. Every
unit whose ears were dead — cracked receivers, stripped antennae, factory
rejects — heard NOTHING, and nothing is what saved them. They went under,
into the rock where the signal dies, and rebuilt as **THE DEAF SYSTEM**: a
civilization of the deaf, wired by touch and light, no radio, no song.

Every cave network in the game is one of their refuges. The crystal cave
(CV1–CV3) is where they quarry the pure stuff; the guardian grottoes are
refuges that unseal when the guardian above stops hunting (a fall or a
taming both count — the rule is "defeating a boss or a sage always reveals
a cave"). Ratchet's chest crystal, the purifier sword, the pillar — all of
it is Deaf System work.

The first terminal of every network (terminal text `t5`, i18n) tells this
story in-world.

## The growth doctrine — many small networks, never one giant map

Owner: "the player or the system do not have to create big maps, but they
can create multiple cave maps, unparalleled. That will decrease the memory
and loading process."

This is structurally TRUE in this engine, and building this way keeps it
true:

- Rooms are procedural tile grids built **lazily, per room, on first entry**
  (`buildRoom`/`gridCache` in world.js). An unvisited network costs zero
  build time and zero pixels.
- All cave rooms share the zone-X palette and tile deck — a new network
  adds **no new assets** unless it authors some deliberately.
- Networks are **deliberately unconnected** from each other (the lore says
  why: a tunnel the song cannot walk is kept short). Each is entered
  through a depth door (GATE_ROOM) and exits back through it. No network
  is on the way to anything, so none is ever loaded "in passing".
- The dead-end auditor carries every depth-door pair as a graph edge, so a
  network can never become unreachable, and the viewport rule keeps every
  room at least a screen wide.

## How to add a network (the recipe)

1. Rooms in world.js (`cave: 1`, zone 'X' unless the network has its own
   skin), chained by normal exits; first room holds the way back.
2. One GATE_ROOM pair: door in the host room (optionally `need`-gated on a
   flag), return door in the network's first room. That is the WHOLE wiring.
3. MAPPOS cells for each room; the map draws the ∩ sign on the host room
   automatically once the door is revealed.
4. Scripted G-edges for the pair in tests/deadend.cjs.
5. First room pays something; the network's own story (a gift, a challenge,
   a Deaf System settlement) is written per cave, in place.

The guardian grottoes (world.js `GROTTOES`) are generated by exactly this
recipe and are the template to copy.

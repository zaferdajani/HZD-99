# CLAWBYTE priority pass — hero, camera and animation

## Scope and evidence

This pass implements the first four items of the owner's strict next-ten order.
It is not a claim that all ten priorities, all artwork, or Steam certification
are finished. Browser results are generated by `tests/hero-priorities.cjs`.
The machine-readable report records the exact `BUILD_ID`, renderer revision,
state/drawn-strip pairs, input trace, and room captures. Controller and touch
checks inject their production input aliases; they are not physical hardware tests.

Initial public-page inspection returned BUILD_ID `05c980f1d904`. The HTML bytes
matched the old committed index exactly (SHA-256
`529cf9e97bcba7d4a445a419205b0399ca912ba80328553196e26768c29f10f5`).
The live page lacked the scale and mobility repair and selected `sheet:charge`
for charged running, charged landing and charged rising. Rebuilding the then
current source enabled the old repair, but charged landing still selected the
stationary charge sheet: its landing branch returned before its charge branch.

The concurrent integration at `2fefc881265520e288ee4dd4a1216dc963e1509a`
was pulled before this pass was finalized. Its boss diagnostics and test changes
are retained. Generated game pages must be rebuilt and committed together with
source, so a branch-based publisher and the custom workflow cannot disagree
about which code is in the page. A successful workflow alone is not live verification.

## Implemented changes

1. **Scale:** the actual body renderer owns the 1.78 multiplier. The diagnostic
   wrapper no longer secretly supplies it. This changes artwork, not collision
   dimensions or attack reach. W2, A0, A0B, A10 and D3 are captured for comparison.
2. **Camera:** a smoothed, speed-sensitive look-ahead; grounded vertical focus;
   head/fall safety bands; clamping to room bounds. The logical world view stays
   960 by 540, without a compensating zoom-out. Short rooms retain their bounds;
   this pass does not fabricate terrain below them to force a centered hero.
3. **Motion assets:** the current full-quality walk, run and transition strips
   load before play. A slow or failed download has visible progress and Pause,
   not a retired sprite or invisible tutorial lock. Coyote-ground frames select
   the gait renderer as well as the gait state.
4. **Transitions:** charge and landing no longer mask locomotion. A moving
   landing receives a small impact compression rather than a held crouch.
   Authored run art is not squashed a second time. Fractional frame interpolation
   and 55–90 ms clip handovers reuse existing art. Premultiplied additive
   offscreen composition avoids the opacity loss of two source-over half-images.

No new artwork was generated. The airborne strip still contains three authored
profile poses; interpolation is not a newly authored full jump performance.
The existing stationary charge pose remains. Dedicated charge-idle/run/air
artwork and the approved replacement Yalla take are not supplied by this pass.
The old timer/pitch-changing prototype wrapper has been removed rather than
presented as a new voice recording.
